# 置身钉内

- **作者**：滕雅辛（幽素）
- **链接**：https://ata.atatech.org/articles/11020656864
- **创建 / 导入日期**：2026-06-04
- **性质**：作者亲历视角的产品复盘与组织观察；判断带有主观经验性，应作为案例材料使用。

## 核心要点

- 文章复盘了 [[项目_钉钉_ONE]] 从立项、发布、共创到收缩的过程，ONE 被定义为“以 Agent 驱动的工作信息流”，目标是让“人找事”变成“事找人”。
- 作者认为 ONE 的多重发心——用户减负、钉钉 AI 入口换代、组织战役、商业化探索——导致产品从一开始就承载过多目标。
- 核心定位张力包括：服务老板还是员工、站在发信人还是收信人一侧、做 To C 式入口还是 To B 深场景。
- 文章强调 [[概念_AI产品主动服务]] 不是简单提前推送工作，而是在重新安排用户、工作、责任和组织权力的关系。
- 卡片式 UI 适合轻处理、审批、待办和会议准备，但承接 IM 消息时会遇到实时性、已读状态、查找效率和迁移成本等问题。
- 用户共创的价值不在于听到“不错”，而在于看见真实工作结构、真实成本和真实承诺；参见 [[概念_AI产品用户验证]]。
- 文章批评“每日一包”式敏捷容易奖励可见变化，而忽视个性化、反馈闭环、权限审计、长期记忆等底层能力；参见 [[概念_AI产品敏捷债]]。
- 企业 Agent 的难点不在聊天，而在上下文、权限、工具调用、失败兜底和执行闭环；参见 [[概念_企业Agent]]。
- 长期视角上，作者强调健康、判断力和人的长期成长：AI 产品开发不能把人只当作项目资源。

## 可迁移洞察

1. **形式不能凌驾于内容**：卡片、Feed、Agent OS 等形态只有在承接真实用户动作时才成立。
2. **默认值就是制度**：默认已读、默认排序、默认推送、默认出现内容流，都在改变用户责任与权力边界。
3. **用户最诚实的回答在成本里**：愿不愿意付时间、迁移路径、承担风险、交出业务流程，比口头评价更可靠。
4. **敏捷应服务学习，而不是服务证明**：真正的敏捷是更快校准问题，而不是每天制造可汇报变化。
5. **Agent 要先打小闭环**：消息、日程、会议、待办、审批等小仗没赢，直接称 Agent OS 容易悬空。

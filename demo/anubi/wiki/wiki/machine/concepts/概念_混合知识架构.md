# 混合知识架构

混合知识架构指把 [[概念_RAG]]、[[概念_LLM_Wiki模式]] 与 Agent 分流结合起来：底层用 RAG 保留原文检索、溯源和合规能力；上层用 Wiki 沉淀结构化理解；中间由 Agent 判断问题该走哪条路径。

## 典型分层

1. **RAG 底座**：负责原文保真、参数查询、制度条款、合规审计。
2. **Wiki 上层**：负责概念解释、跨文档综合、长期知识沉淀。
3. **Agent 枢纽**：负责识别用户意图，在检索、Wiki 导航、二者融合之间切换。

## 为什么需要混合

- 纯 RAG 不擅长长期积累和跨文档综合。
- 纯 LLM Wiki 不擅长强溯源、实时更新和企业级权限 / 并发。
- 混合架构试图同时获得“原文可信”和“知识复利”。

## 适用问题分流

| 问题类型 | 更适合路径 |
|----------|------------|
| 查制度原文、参数、表格、条款 | RAG |
| 做主题综述、概念解释、跨资料关系分析 | Wiki |
| 既要综合结论又要原文证据 | Wiki + RAG |

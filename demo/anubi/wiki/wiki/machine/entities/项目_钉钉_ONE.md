# 钉钉 ONE

钉钉 ONE 是来源 [[置身钉内]] 中复盘的企业 AI 产品项目。文中称，它是钉钉在无招回归后主推的 AI 原生项目之一，目标是把消息、日程、待办、会议、文档等工作信息重新组织为一个“事找人”的 AI 工作信息流。

## 产品发心

[[置身钉内]] 将 ONE 的发心拆成四层：

1. **用户发心**：缓解工作信息分散、消息爆炸和事项遗漏。
2. **产品发心**：为钉钉建立 AI 时代的新入口，而不是只把 AI 做成聊天框或老功能插件。
3. **组织发心**：作为组织战役，凝聚团队、重塑钉钉形象。
4. **商业发心**：为 AI token、模型能力和工作流场景寻找消化路径。

## 定位

来源中对 ONE 的定位可概括为：

| 问题 | ONE 的答案 |
|------|------------|
| 为谁 | 高信息密度、高协作负担、对消息 / 日程 / 任务闭环负责的钉钉用户 |
| 在哪用 | 钉钉内工作信息流，尤其是消息、日程、待办、听记之间 |
| 解决什么 | 消息太多、事项太散、重点不清、容易漏回、任务难闭环 |
| 为什么是钉钉 | 钉钉有组织关系、消息、日程、会议、审批、待办和真实工作流 context |

## 关键张力

- **老板 vs 员工**：管理者需要掌控与督办，普通员工需要减负与少被打扰。
- **发信人 vs 收信人**：钉钉历史上偏发信人立场，但 ONE 的“秘书”叙事又需要保护收信人的注意力和心理缓冲。
- **To C 入口 vs To B 深场景**：ONE 想做所有人的入口，但企业客户往往需要贴合自身流程的深度定制。
- **移动端卡片 vs 复杂工作**：移动端适合提醒和轻处理，却不适合完整承接复杂工作流。

## 设计教训

- 卡片适合审批、待办、会议准备等结构清晰、动作明确的场景。
- IM 消息进入卡片后，会遭遇实时性、已读状态、上下文不足、会话查找效率和用户迁移成本问题。
- 主动服务必须计算责任成本：系统把工作提前端到用户面前，也可能提前启动用户的责任压力。
- 后期信息流形态相对卡片更接近“一屏内处理紧急重要事项”的需求。
